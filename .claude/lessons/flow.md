# Orchestrator-Lessons (flow) — newest-first

- **Board-Read erst NACH Wechsel in einen frischen Worktree (origin/main).** `git fetch` aktualisiert nur die Remote-Refs — `board next`/`board show` lesen den Working-Tree des cwd. Ein `/flow`-Start im stale Hauptordner kann eine auf origin/main bereits `Done` gelandete Story erneut claimen und ihr Done überschreiben (der Claim-Push geht als Fast-Forward durch, weil der Worktree frisch von origin/main abzweigt). Reihenfolge: EnterWorktree (fresh von origin/main) → DORT `board next` → Claim. Recovery: Story-YAML per `git checkout <origin-sha> -- board/stories/<story>-*.yaml` zurücksetzen, committen, pushen. *[seen-in: research-app S-001 2026-07-27 — Done-Flip f78ae15 um 07:30Z, Re-Claim um 07:32Z aus stale Hauptordner-Read]*
- **Headless-Abbruch vor Ship-Abschluss hinterlässt Ledger-Lücken.** S-001 hatte ZWEI komplette Gate-Läufe (bis tester-PASS), Code gelandet, Done mechanisch nachgezogen — aber keine `items.jsonl`-Zeile, kein Dispo-Spiegel, keine ID-Freigabe. Beim Aufgreifen einer solchen Story: Done-Touchpoint nachziehen (`metrics-append-item.sh` + `metrics-collect.sh` + Dispo-Spiegel via `board set`), `board-id-reserve.sh release` (idempotent). *[seen-in: research-app S-001 2026-07-27]*
